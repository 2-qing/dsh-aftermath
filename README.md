# dsh-aftermath

![dsh-aftermath](assets/icon-96.png)

[![npm version](https://img.shields.io/npm/v/dsh-aftermath.svg)](https://www.npmjs.com/package/dsh-aftermath)
[![npm downloads](https://img.shields.io/npm/dm/dsh-aftermath.svg)](https://www.npmjs.com/package/dsh-aftermath)

用于记录每轮对话期间观测目录内的文件变更（新建、删除、修改），并推断大致是哪次工具调用引发了变更，以便在发生意外修改时进行溯源与排查。

本插件为零依赖实现：不访问外部网络，不读取文件正文内容。

它针对 Windows 环境下 DSH 沙箱隔离的不足：Linux / macOS 提供 `bwrap`、Seatbelt 等进程级隔离机制，DSH 在 Windows 上则依赖基于 ACL 的受限令牌（restricted-token）后端，且该后端不可用时命令会直接以 fail-closed 模式拒绝执行。为让 Agent 能够完成实际任务，不少用户会切换至拥有完整权限的 `danger-full-access` 模式——这意味着 Agent 发起的 bash / PowerShell 命令将继承宿主进程的完整文件权限并直接作用于真实磁盘，一旦发生误删、路径覆盖或误执行 `rm -rf`，变更将立即生效且不可逆。本插件将观测维度下沉至文件系统层，通过在每轮对话前后对观测目录执行快照对比，使缺少沙箱的环境下仍可事后倒查：哪些文件被改动，大致对应哪次工具调用。需要明确的是，本插件只做事后留痕，不预防误操作、不备份文件内容，也不提供回滚。

> 傻瓜式指引请参阅 [GUIDE.md](GUIDE.md)。

## 使用方式

插件安装后即自动开启记录。可通过以下三种方式查看变更记录：

1. **可视化面板**：在 Plugins 页面顶部标签栏点击「变更记录」，查看最近 8 轮对话的逐条文件变更及归因详情。
2. **自然语言查询**：直接在对话中询问 Agent（例如「桌面图标为什么全变白了」），Agent 将自动调用 `aftermath_history` 工具检索历史记录。
3. **斜杠指令**：在对话中输入 `/aftermath report --last 1` 等指令查询明细（完整指令列表详见下文）。

所有记录默认持久化存储于 `$DSH_HOME/state/aftermath/` 目录下。

## 「变更记录」标签页

- **记录列表**：每行展示单轮摘要（如 `16:24 #50 新建 1 · 修改 4`），展开后可查看逐条明细（如 `✔ 新建 ~\Desktop\a.txt bash · cp 确定`，依次为置信度标记、变更类型、路径、依据与置信度档位）。
- **外部变更提示**：若观测目录内无文件变化，但本轮执行了文件写入类操作，面板将显示黄色提示「可能改在别处」。
- **路径线索汇总**：页面底部单独列出「命令提到、但不在观测目录内的路径」。
- **数据刷新**：点击右上角「刷新」可重新加载最新状态；其读取的是与 `/aftermath report` 同一份落盘记录（面板仅取最近 8 轮，并精简字段）。

面板数据通过插件在 Host 层注册的只读路由 `GET /aftermath/recent` 获取：该路由不依赖会话与 Agent，因此新开的窗口同样可以查看；仅响应 GET/HEAD 请求，并携带 `cache-control: no-store` 响应头；返回内容中的路径已按配置脱敏。需要说明的是，服务端不做 Origin 校验与鉴权，同源仅是浏览器对 `fetch` 的限制——本机其它进程若得知本地端口，仍可直接请求该接口。

## 工作原理

在实际使用中，文件误操作常见的一类来源并非标准 `write` / `edit` 工具，而是 Agent 直接通过 `pwsh` / `bash` 执行了修改磁盘的底层命令，这类操作无法被工具调用层的 Hook 捕获。因此，本插件直接基于文件系统层实现观测：

- **快照对比**：在每轮对话开始与结束时，分别对观测目录执行一次文件系统快照（实测 48 个桌面条目耗时约 0.3 ms），通过前后差异生成变更列表。
- **调用计时**：记录每次工具调用的起止时间戳（分别在 `tool/call` 与 `tool/result` 阶段打点）。
- **证据归因**：结合同一轮次内的工具调用记录，为每条文件变更分配归因置信度，共分为四个等级：

| 置信度 | 判定标准 |
| :--- | :--- |
| ✔确定 | 工具调用的命令文本中明确包含该文件的绝对路径 |
| ◐很可能 | 命令操作目标指向该文件所在目录，或本轮仅有该工具调用提及了此文件名 |
| ○时间窗内 | 文件修改时间（mtime）落于某次工具调用的起止区间，或仅落在整轮对话的时间窗口内 |
| ？无法归因 | 缺乏有效关联证据；报告将附上该轮原始命令供人工排查 |

关于「时间窗内」的细分规则：系统优先匹配单次工具调用的起止区间（窗口较窄，误匹配率远低于整轮）；若均未命中，则回退至整轮对话的时间窗口。两者在表格中分别显示为 `○区间内`（对应 `call-interval`）与 `○时间窗内`（对应 `turn-window`）；调用尚未返回时标注 `区间内·未封口`（`call-interval-open`），变更缺少发生时间而只能落在整轮窗口时标注 `时间窗内·无发生时间`（`mutating-call-in-turn`）。

### 观测目录外的变更线索

- **静默写操作记录**：当观测目录内未检测到文件变化，但本轮执行了写入类操作时，系统会生成一条仅包含命令摘要的轻量记录（`kind: quiet`），并在历史列表中显示为 `0（写过 N 条命令，根外？）`。
- **外部路径提取**：工具调用中出现的绝对路径会被记入日志，并在报告中单独归类为「命令提到、但不在观测根内的路径」（该功能仅提取命令文本，不执行全盘扫描）。
- 若无需记录静默轮次，可在配置中将 `recordQuietTurns` 设为 `false`。

### 写入操作判定规则

- **重定向识别**：包含输出重定向符（`>`、`>>`、`2>`）或 `Out-File` 的命令均判定为写入操作，其目标路径纳入归因证据；引号内的 `>` 视为普通文本，不作解析。
- **路径格式归一化**：自动将 `/c/Users/...` 等 Git Bash 风格路径转换为 `C:\Users\...` 后再进行比对。
- **命令语义解析**：根据具体子命令动作区分读写属性（例如 `powershell -c "Get-Content x"` 判定为读取，`powershell -c "Remove-Item x"` 判定为写入）；对于无法明确解析动作的指令（如 `node build.js`），按保守原则归为写入操作。
- **载荷字段隔离**：仅从命令参数与路径参数中提取归因证据，自动忽略 `content` / `prompt` 等正文载荷字段——避免因工具正文恰好包含 `Out-File` 字样及桌面路径而引发误判。

注：纯只读命令提及的路径不作为变更归因依据；若某个观测目录在本轮扫描中未完整遍历，系统将跳过该目录的变更比对，避免将未扫描到的文件误报为删除。

```text
## 报告健康度
- 快照耗时：本轮结束这次扫描 1 ms，覆盖 2 个根 / 446 个条目
- 归因分布：✔确定 2（50%） · ◐很可能 1（25%） · ○时间窗内 1（25%） · ？无法归因 0（0%）
- 时间证据：0 处 mtime 落在某次调用的起止区间内，1 处只落在整轮宽窗
- 调用区间：5 次调用、3 次写操作，3/3 拿到起止时刻（容差 1500 ms）

可能的症状：桌面图标变白/空白
  1) 检查快捷方式是否失效：powershell -c "..."
  2) 刷新图标缓存：ie4uinit.exe -show
```

变更列表之后、`可能的症状` 之前的「报告健康度」用于评估当前记录的可信度，包含扫描耗时、覆盖条目总数、各置信度占比、成功获取起止时间戳的调用比例，以及是否触发条目上限截断等指标。

## 与直接查阅会话日志的对比

会话日志记录的是「Agent 发出了什么指令」，而本插件记录的是「磁盘实际发生了什么变更」，两者在定位上互为补充：

| 对比维度 | 翻阅会话日志 | dsh-aftermath |
|---|---|---|
| **核心内容** | 意图层：工具名称、调用参数、命令原文与返回值 | 结果层：具体被新建/删除/修改的文件、体积及 mtime |
| **排查修改范围** | 需逐条通读命令，并人工推演 rm -rf、git checkout 或脚本内部的实际副作用 | 直接输出结构化变更列表，自动归类整理 |
| **命令执行失败时** | 日志仍保留原命令及报错堆栈，易造成「已执行修改」的误判 | 磁盘状态未发生变化，变更表中不会产生干扰记录 |
| **多源操作覆盖** | write/edit、bash、pwsh、子代理及后台进程分散在不同步骤中，需手动拼接上下文 | 仅关注最终磁盘结果，统一汇总所有来源的文件变动 |
| **调用归因准确性** | 日志时间戳为事件触发时刻，文件 mtime 为磁盘写入时刻，人工对齐耗时且易出错 | 自动进行调用时间区间匹配，明确标注依据级别 |
| **历史溯源能力** | 长对话会触发上下文压缩或裁剪，早期工具输出可能丢失 | 独立持久化为 NDJSON 存档，支持通过 --since 2h 一键检索或使用 grep / jq 分析 |
| **跨会话追踪** | 各会话日志相互独立，缺乏全局视角 | 记录按日期归档并关联会话短标，支持跨会话横向对比 |

归因分析同样基于工具调用文本提取证据，与会话日志同源；不同之处在于，报告将客观事实（磁盘变更）与分析推测（归因等级）明确分离，并在证据不足时直接标注 ？，避免误导排查。

## 安装

支持以下三种安装方式，任选其一即可：

```bash
# 方式一：通过 npm 安装（推荐）
dsh plugin --profile <你的 profile> add dsh-aftermath

# 方式二：通过 GitHub 仓库安装
dsh plugin --profile <你的 profile> add github:2-qing/dsh-aftermath
```

**方式三（本地加载）**：在界面中依次点击 **Plugins → Add plugin → 选择本地插件目录**。

> 环境要求：DSH `>=0.2.2-0 <0.3.0`，Node.js `>=22.12.0`。

## 配置说明

### 图形界面设置

打开 Plugins 页面中的 dsh-aftermath 详情卡片，可直接调整以下参数：插件总开关、观测目录列表（每行一个路径）、遍历深度、历史记录保留天数、路径脱敏开关、是否自动纳入当前会话工作目录（followCwd），以及是否在无变更但执行写操作时保留轻量记录（recordQuietTurns）。

总开关点击后即时生效；其余配置项修改后需点击「保存」。配置采用逐字段写入机制，若某个字段未通过宿主校验，保存操作将停留在对应条目并提示具体错误。所有配置保存后于下一轮对话开始前重新读取生效，无需重启服务。

### 配置文件（YAML）

也可在对应 profile 的 cordis.patch.yml 中直接编辑 config 节点（所有字段均提供默认值）：

```yaml
- id: dsh-aftermath
  config:
    roots: [desktop, downloads, documents] # 内置目录标识或绝对路径，支持 "id=路径" 格式
    depth: 2                               # 遍历深度（0 表示仅扫描根目录当前层）
    exclude: ['node_modules', '~$*']       # 排除的文件名或通配符
    extraRoots: ['D:\项目']                # 额外追加的观测根目录
    retentionDays: 7                       # 历史记录保留天数
    maskHome: true                         # 在报告中将用户主目录路径脱敏为 ~
    intervalSlackMs: 1500                  # 调用时间区间归因容差（毫秒），0 表示严格对齐
    followCwd: true                        # 自动将当前会话的工作目录纳入观测范围（仅扫描顶层）
    recordQuietTurns: true                 # 观测目录无变化但执行写操作时，保留命令摘要轻量记录
```

内置目录标识支持 desktop、downloads、documents、pictures、music、videos，系统将按顺序自动探测 %USERPROFILE%\<目录名>、OneDrive\<目录名> 以及对应的中文目录名（如 桌面、下载）。

针对 Windows 系统中常见的桌面路径被 OneDrive 重定向的情况，插件不依赖系统注册表，而是通过路径别名探测并结合显式配置确定目标。建议运行 /aftermath roots 核对实际生效的观测目录。

## 默认排除列表

为避免无关文件干扰报告可读性并控制扫描开销，以下名称或模式默认不纳入扫描（exclude 匹配对象为文件名或通配符而非完整路径，且不区分大小写）：

| 排除条目 | 排除原因 |
|---|---|
| node_modules | 依赖包目录文件数量庞大，且可通过包管理器随时重新安装 |
| .git .svn .vs | 版本控制系统与 IDE 内部元数据目录，其变动不代表业务文件修改 |
| ~$* | Office 文档打开时生成的临时锁文件，频繁创建与删除易产生噪音 |
| Thumbs.db desktop.ini .DS_Store | 操作系统或访达生成的缩略图缓存与文件夹视图配置文件 |
| $RECYCLE.BIN | 系统回收站目录，避免将已删除文件移动至回收站的行为重复统计 |
| System Volume Information | Windows 卷影副本等底层系统信息目录 |
| dist build .next .turbo coverage | 前端及构建工具生成的编译产物与测试覆盖率报告 |
| __pycache__ .venv venv .mypy_cache .pytest_cache | Python 字节码缓存、虚拟环境及测试/类型检查缓存 |
| target | Rust / Maven 项目的默认构建输出目录 |

若排除规则配置不足，当 followCwd 指向条目上千的大型代码仓库时，单轮扫描耗时将从十几毫秒上升至两百毫秒量级，报告也会被大量构建产物淹没。

**自定义排除规则的两种方式**：

 * **自定义排除项**：将需要忽略的名称写入 exclude 数组（注意：YAML 配置中的数组为**整体覆盖**而非追加，修改时请保留所需的默认项）。
 * **取消特定排除**：若需监控名为 build 等默认被忽略的目录，将其从 exclude 数组中移除即可。

| 指令语法 | 功能说明 |
|---|---|
| /aftermath report [--last N] [--since 2h] [--turn N [--session x]] [--root desktop] [--include-read] [--save] | 查看指定范围的文件变更明细与归因分析 |
| /aftermath scan [--keep] | 立即执行一次手动扫描，并与上一次基线快照进行对比 |

| /aftermath status | 查看当前配置概览、存档路径、记录总数、占用体积、数据完整性及已钉住日期 |
| /aftermath pin [2026-11-18 \| last] | 钉住指定日期的记录，使其免受 retentionDays 自动清理策略影响 |
| /aftermath unpin [2026-11-18 \| last \| --all] | 解除指定或全部日期的记录钉住状态 |
| /aftermath pins | 列出当前所有已钉住的日期及其占用的存储空间 |
| /aftermath doctor | 运行环境自检，验证配置命名空间及 Schema 加载状态 |
| /aftermath help | 显示指令帮助信息 |

**参数补充说明**：

 * --save：将完整分析报告持久化保存至 $DSH_HOME/state/aftermath/reports/ 目录。
 * --include-read：在「命令提到、但不在观测根内的路径」一节中，一并展示纯只读命令（如 ls、cat）提及的路径（默认仅展示可能引发写入的调用路径）。

## Agent 专用工具

插件向模型注册了只读查询工具 aftermath_history（支持 since、root、limit 参数）。启用后，Agent 可自主查询历史文件变更记录（例如核实「上一轮删除了哪些文件」），无需用户手动翻阅日志。

## 数据存储与隐私安全

```text
$DSH_HOME/state/aftermath/
├── baseline.json          # 最近一次文件系统基线快照（用于空闲期对比）
├── turns/2026-11-17.ndjson # 按日期切分的逐轮变更记录
└── reports/               # 通过 --save 参数导出的分析报告
```

### 隐私保护机制

 * **最小化采集**：仅采集文件路径、体积及修改时间（mtime），绝不读取文件正文内容。
 * **路径与命令脱敏**：敏感文件名（如 .env*、*.pem、*.key、*.kdbx、id_rsa、kubeconfig 等）及 .ssh/、.aws/、.gnupg 等敏感目录下的子路径，在报告、前端面板及 Agent 工具返回值中一律替换为 ***。命令原文仅保留用于归因说明的片段（不超过 180 字符），且单次调用最多提取 12 条绝对路径（每条不超过 320 字符）。
 * **凭据清洗**：命令摘要在写入磁盘前会执行脱敏过滤，将 Authorization:、Bearer、password=、--token=、ghp_、AKIA、sk- 等常见密钥字段值替换为 [redacted]（此举旨在防止敏感信息在界面扩散，会话日志本身仍保留原始命令）。
 * **生命周期管理**：历史记录依据 retentionDays 自动清理（已钉住的日期除外）。若读入损坏的日志行，系统会将其转存至 state/aftermath/corrupt.log，并在 status 与报告中提示「记录没读全」。当存档总体积超过 storageWarnMB（默认 200 MB）时，系统仅发出空间预警，不会执行静默删除。

> **关于脱敏边界的说明**：上述 *** 与 ~ 掩码仅作用于报告输出、前端面板及 Agent 工具返回文本；本地 turns/*.ndjson 文件中仍存储原始路径与脱敏后的命令片段，以确保溯源准确性。如需彻底清除本地历史记录，请调小 retentionDays 配置或手动删除 state/aftermath/ 目录。

记录格式版本为 v: 2，每条记录的 kind 字段分为 changes（存在实际文件变更）与 quiet（无文件变更但执行了写操作，仅保留命令摘要，不含变更列表）。此外，纯只读回合不写入 turns 明细（避免无谓落盘），但会以轮次计数形式记录于 state/aftermath/meta.json；因此 status 与面板能够区分「本轮没有文件变更」与「插件根本没有在运行」。

### 回收站可恢复性标注

对于已删除的文件，若检测到其仍在系统回收站中，报告与面板将在删除行后标注 ♻（可恢复）；若回收站已扫描但无匹配项，标注 ✗（很可能已永久删除）；无法读取回收站状态时标注 ?。报告另在变更表下方附「回收站」小节，逐条说明每个被删条目的判定结果。

该状态通过只读解析 $Recycle.Bin\<SID>\$I* 元数据得出，匹配条件为「原始路径一致 + 文件大小一致 + 删除时刻落在本轮时间窗口内」三重一致；版本字段仅用于判定记录格式、定位各字段偏移，不参与匹配。整个过程严格遵守 fs:read 权限边界，不触碰 $R 实际数据文件，也不执行任何恢复或删除操作。（注：0.7.0 版本之前生成的旧记录不含该元数据字段，故不显示此标记。）

### 权限声明说明

插件在 dsh.capabilities 中声明了 fs:read、tools:register 与 network:ingress 权限，并在 dsh.labels 中声明了 remote-access。

 * **network:ingress 声明依据**：插件在运行时通过 ctx.inject(['webServer']) 动态注册了只读路由 GET /aftermath/recent。由于 dsh-standards 的静态代码检查无法识别动态路由注册，会触发预期内的 C-11.5 提示，但该权限声明完全真实有效。该路由仅响应 GET/HEAD 请求，返回经 maskHome 脱敏后的本地记录，不提供任何写入或删除接口。
 * **未声明 network:egress 说明**：静态检查可能会报出一条 C-11.2 提示（检测到 egress 触发点但未声明权限），这是因为检查器将客户端的 fetch('/aftermath/recent') 误判为外部网络请求。实际上，GUI 前端与后端服务运行在同一本地环回（loopback）端口下，该请求属于同源本地通信，不会向任何外部地址发送数据，因此无需声明 network:egress。

## 已知限制

 * **观测边界**：仅监控配置指定的观测目录及遍历深度，目录范围之外的磁盘状态变更无法直接感知，仅能通过「命令文本提及的路径」提供间接线索。
 * **扫描截断保护**：当某观测目录内条目数超出上限或子目录无法读取时，系统将跳过该目录的本轮比对，并在报告开头提示「本轮观测不完整」，避免将未扫描文件误判为删除；同时这一轮不更新基线快照，下一轮仍以旧基线为准。
 * **移动操作识别**：moved 状态基于启发式规则（同名 + 相同大小 + 相近 mtime）进行推断，并在报告中予以标注。
 * **归因局限性**：归因完全依赖命令文本、所在目录与时间窗口证据，缺乏有效证据时将直接标为 ？。
 * **异步与后台进程**：调用时间区间依赖宿主返回的 tool/result 时机；若命令通过 Start-Process 或 & 拉起后台进程，实际文件修改可能发生在调用区间结束之后，此时归因将回落至整轮时间窗口或无法归因。
 * **仅记录不回滚**：本插件专注于变更观测与审计，仅记录文件路径元数据而不备份文件内容，不提供自动回滚功能。
 * **回收站状态快照**：回收站可恢复标记仅在文件删除当轮进行判定，后续用户手动清空或还原回收站不会同步更新历史记录中的既有标记。
