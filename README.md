# dsh-aftermath

![dsh-aftermath](assets/icon-96.png)

记录 AI 每轮对话对观测目录的文件改动。出事之后可以倒查：改了哪些文件、大概是哪条命令改的、怎么恢复。

DSH 插件，零依赖，不联网，不读文件内容。

> 第一次用、不想看技术细节：直接看 [GUIDE.md](GUIDE.md)，照着做就行。

## 用法

装上就不用管，它自己记。出事之后三条路，任选：

1. **Plugins 页直接看**：Plugins 页顶部标签栏里点「变更记录」——最近 8 轮、点开看逐条变更与归因。这个页面不依赖对话，新开的窗口也能看。
2. **跟 agent 说一句**「桌面图标怎么全白了」，它会调 `aftermath_history` 查上一轮删了什么。
3. **自己输命令** `/aftermath report --last 1` 看明细。

记录存在 `$DSH_HOME/state/aftermath/`。

## Plugins 页的「变更记录」标签页

在 Plugins 页标签栏（「已安装」旁边）多出一个「变更记录」，点进去就是它；dsh-aftermath 的设置卡片里只留一行指路。打开后先看到今天的轮次与变更数，往下一轮一行：

- `16:24 #50 新建 1 · 修改 4` —— 点一行展开，逐条列出 `✔ 新建 ~\Desktop\a.txt 确定`；
- 这一轮观测目录内**没变化但执行过写操作**时，那一行显示黄色提示「可能改在别处」，不留空；
- 面板底部单独列「命令提到、但不在观测目录内的路径」，也就是根外的线索；
- 右上角「刷新」重新读一遍，数据与 `/aftermath report` 同一份，不额外落盘。

为什么它能用而命令不能：斜杠命令必须绑一个已存在的会话，而这个标签页没有会话；数据走 Host 自己注册的只读路由 `GET /aftermath/recent`（同源、只读、`cache-control: no-store`），所以不需要对话。

为什么不做成插件详情页里的卡片：`plugins.bundle.config` 槽位按宿主契约渲染在插件描述与 README **之后**，卡片内部再置顶也压不过 README，所以改用独立的 `plugins.tab` 槽位。

## 工作方式

很多事故不是 `write`/`edit` 工具造成的，而是 agent 跑了一条 `pwsh`/`bash` 命令直接改磁盘——只在工具调用层做 hook 看不到这类改动。所以 aftermath 在文件系统层观测：

- 每轮开始和结束各对观测目录做一次快照（桌面 48 条实测约 0.3 ms），做差得到变更列表；
- 同时记下每次工具调用的起止时刻（`tool/call` 与 `tool/result` 各带一个时间）；
- 拿同一轮的调用证据给每条变更标归因，归因分四档，报告里逐条标注：

| 档位 | 判据 |
| --- | --- |
| ✔ 确定 | 命令里出现该文件的绝对路径 |
| ◐ 很可能 | 命令在处理这个目录，或本轮只有它提到这个文件名 |
| ○ 时间窗内 | 改动 mtime 落在某次调用的起止区间内（没等到结束时刻就落到整轮宽窗） |
| ？ 无法归因 | 没有证据。报告会写明，并附上该轮命令原文供自己判断 |

「时间窗内」分两级：先比**这一次调用自己的区间**（窄，几乎不会错配到别的调用）；区间全不命中，才退回**整个回合的宽窗**，那时它只说明「这一轮里有人动过」。表格的归因列会区分这两级，写成 `○区间内` 与 `○时间窗内`，依据列再给出具体判据（`call-interval` / `turn-window`）。

**观测根之外也不会完全瞎：**

- 一轮里观测根内没有变化、但确实执行过写操作时，仍会留一条轻记录（只含命令摘要，`kind: quiet`）。报告会写「这道改动可能落在根外」并列出命令原文，历史表里显示 `0（写过 N 条命令，根外？）`。
- 每次工具调用里出现过的绝对路径都会存进记录，报告多一节「命令提到、但不在观测根内的路径」。它**不扫盘**，只说「命令提到过」，所以写清了「插件没看过它们的磁盘状态」。
- 不想要这些轻记录，把 `recordQuietTurns` 设成 `false` 即可。

判「写操作」的规则：

- `printf x > a.txt` 这类靠重定向落盘的写法也算写（`>` / `>>` / `2>` / `Out-File` 都认），目标路径计入证据；引号里的 `>` 是文本，不算；
- `/c/Users/...` 这种 Git Bash 路径会翻成 `C:\Users\...` 再比对，不会因为写法不同就认不出来；
- `powershell -c "Get-Content x"` 是读、`powershell -c "Remove-Item x"` 是写：先看里面的动词，两者都对不上（`node build.js`）时才保守地算写；
- 只从命令参数和路径参数里取证据，`content` / `prompt` 这类载荷文本不参与。否则某个工具的参数里碰巧写了 `Out-File` 和一条桌面路径，那个文件就会被标成「确定」——这是真机记录里抓到过的误判。

否则这类调用会被当成只读，白白丢掉区间证据。

两条规则：只读命令不算证据（`Get-Content a.txt` 提到路径但不会把 a.txt 标成「确定」）；某个目录这轮扫描失败时整根跳过，不会误报一排「删除」。

报告长这样：

```
第 12 轮 · 2026-11-17 20:41 · 会话 #7
共 4 处变更：删除 3 · 修改 1
归因：✔确定 2 · ◐很可能 1 · ○时间窗内 1 · ？无法归因 0

| 变更 | 条目 | 大小 | 时间 | 归因 | 依据 |
| --- | --- | --- | --- | --- | --- |
| 删除 | Desktop\微信.lnk | 1.2 KB | 20:41:03 | ✔ 确定 | 命令里出现该绝对路径（bash） |
| 删除 | Desktop\QQ.lnk | 1.1 KB | 20:41:03 | ◐ 很可能 | 该调用在处理 Desktop\ 下的文件 |
| 修改 | Desktop\desktop.ini | 218 B | 20:41:04 | ○ 区间内 | 落在 bash 这次调用的起止区间内 |

报告健康度
- 快照耗时：本轮结束这次扫描 1 ms，覆盖 2 个根 / 446 个条目
- 归因分布：✔确定 2（50%） · ◐很可能 1（25%） · ○时间窗内 1（25%） · ？无法归因 0（0%）
- 时间证据：1 处 mtime 落在某次调用的起止区间内，0 处只落在整轮宽窗
- 调用区间：5 次调用、3 次写操作，3/3 拿到起止时刻（容差 1500 ms）

可能的症状：桌面图标变白/空白
  1) 检查快捷方式是否失效：powershell -c "..."
  2) 刷新图标缓存：ie4uinit.exe -show
```

末尾那段「报告健康度」是这份记录自己的可信度证据：扫描耗时、覆盖了多少条目、四档归因各占多少、有几条调用真正拿到了起止时刻、有没有因为条数上限被截断。数字难看的时候，就不该拿它当定论。

## 相比直接翻日志

会话日志里已经有每次工具调用和命令原文，那还需要这个插件吗？需要的地方在于：**日志记的是「发出了什么命令」，插件记的是「磁盘上留下了什么」。**

| | 翻会话日志 | dsh-aftermath |
| --- | --- | --- |
| 内容 | 意图层：工具名、参数、命令原文、返回值 | 结果层：哪个文件被建/删/改、大小与 mtime |
| 要回答「这轮改了哪些文件」 | 得自己把命令逐条读一遍，再脑内模拟 `rm -rf`、`git checkout`、脚本内部调用的效果 | 直接给变更表，四类分好 |
| 命令失败了会怎样 | 日志里照样有那条命令和报错，容易当成“干过这件事” | 磁盘没有变化，就不会出现在变更表里 |
| 覆盖范围 | `write`/`edit`、`bash`、`pwsh`、子代理、后台进程散在不同 step，得自己拼 | 只看磁盘结果，谁干的都要过这道账 |
| 判断是哪次调用造成的 | 日志时间戳是事件时刻，文件 mtime 是磁盘时刻，人工对时容易错 | 调用区间配对，误差有容差，依据列写明是哪一级 |
| 事后还查得到吗 | 长会话会被压缩/裁剪，早期工具输出可能已经不在上下文里；翻几十轮也很费劲 | 独立 NDJSON 存档，`--since 2h` 一条命令，还能 grep / jq |
| 看得懂吗 | 一堆命令与返回 | 先给结论、症状对应的检查命令，再给逐条明细 |
| 跨会话 | 每次对话各看各的 | 记录按日存、带会话短标，可以横向对比 |

要诚实的地方：**“是哪条命令干的”这个判断，插件同样只能从 `tool/call` 的文本里取证据**，和翻日志的信息源是同一个。差别在于它把「事实」和「猜测」分开了——磁盘上的变更是事实，归因是分级猜测，报告里逐条标出档位，标 `？` 就是真的没证据。

一句话：日志告诉你它**说过要做什么**，插件告诉你它**实际做成了什么**。两个都要看，只是顺序是插件先给事实、日志再给上下文。

## 安装

**Plugins → Add plugin → 选这个目录**。要求 DSH `>=0.2.2-0 <0.3.0`、Node `>=22.12.0`。

## 设置

Plugins 页打开 dsh-aftermath 的详情，卡片里能改：

- 总开关（关掉立即停止快照，历史记录保留可查）
- 观测目录（一行一个，内置标识或绝对路径）
- 递归深度、保留天数、路径打码

总开关点一下即时写入；其余几项改完点保存。保存是逐字段写入的：某个字段被宿主拒绝就停在那一条并显示失败，不会显示「已保存」。保存后立即生效，不用重启插件。

卡片能不能改这些字段，取决于宿主有没有拿到插件的设置 schema。用 `link:` 方式安装（本地开发目录）时，Node 默认按真实路径解析模块，插件目录可能和依赖不在同一个盘，`lib/schema.js` 因此按 `DSH_PROFILE_DIR`、`DSH_INSTALL_DIR`、`$DSH_HOME`、以及 exe 旁边的 `resources/app.asar/dsh/node_modules` 逐处找 `@deepseek-ai/schemastery`。

怀疑卡片不对劲时先跑 `/aftermath doctor`：它会打印 Config 是否导出、schema 从哪加载的、宿主给本插件建的设置命名空间在不在。同一份自检在每次启动时也会写到 `$DSH_HOME/state/aftermath/settings-probe.json`。如果确认 schema 没加载到，卡片里只会剩总开关，这时改用下面的 yml 配置。

## 配置（yml）

在 profile 的 `cordis.patch.yml` 里写 config，全部有默认值：

```yaml
- id: dsh-aftermath
  config:
    roots: [desktop, downloads, documents]   # 内置标识或绝对路径，支持 "id=路径"
    depth: 2                      # 0 = 只看根目录这一层
    exclude: ['node_modules', '~$*']
    extraRoots: ['D:\项目']
    retentionDays: 7
    maskHome: true                # 报告里把家目录打码成 ~
    intervalSlackMs: 1500         # 调用区间归因的容差（毫秒），0 = 严丝合缝
    followCwd: true               # 当前会话的工作目录自动算进观测根（大目录只看顶层）
    recordQuietTurns: true        # 根内没变化、但执行过写操作时，也记一条只有命令摘要的轻记录
```

内置标识：`desktop`、`downloads`、`documents`、`pictures`、`music`、`videos`，依次探测 `%USERPROFILE%\<名>`、`OneDrive\<名>`、中文名（`桌面`/`下载`）。

Windows 上桌面被 OneDrive 重定向很常见。插件不读注册表，路径靠别名探测加显式配置，跑 `/aftermath roots` 确认实际观测的目录对不对。

## 默认排除表

下面这些名字默认不扫（`exclude` 里写的是名字或通配，不是路径；大小写不敏感）：

| 条目 | 为什么排除 |
| --- | --- |
| `node_modules` | 依赖目录，动辄几万个文件；删了重装即可 |
| `.git` `.svn` `.vs` | 版本库与 IDE 的内部目录，改动不反映你自己的文件 |
| `~$*` | Office 打开文档时生成的锁文件，开合一次就变，天天报一堆「新建/删除」 |
| `Thumbs.db` `desktop.ini` `.DS_Store` | 系统/访达的缩略图与文件夹配置，被反复重写 |
| `$RECYCLE.BIN` | 回收站：删掉的文件会落到这里，扫进来会把「删除」再报一遍 |
| `System Volume Information` | 卷影副本等系统信息 |
| `dist` `build` `.next` `.turbo` `coverage` | 构建产物与覆盖率报告，文件多、删了能重新生成 |
| `__pycache__` `.venv` `venv` `.mypy_cache` `.pytest_cache` | Python 缓存与虚拟环境 |
| `target` | Rust / Maven 的构建目录 |

默认值是为了让报告可读：不排除的话，`cwd` 自动跟随一旦落在大仓库上，一轮扫描会从几十毫秒涨到几百毫秒，报告里还会塞满构建产物。

两种改法：

- 想加：把新名字写进 `exclude` 数组（yml 里这个数组是**整体替换**，不是追加）
- 想减：如果某个目录叫 `build` 但里面确实有你心疼的文件，把它从数组里去掉

被排除的目录**不进快照、也不进报告**——排除的语义是「当它不存在」，不是「看到但不记」。

## 命令

| 命令 | 作用 |
| --- | --- |
| `/aftermath report [--last N] [--since 2h] [--root desktop] [--save]` | 变更明细与归因 |
| `/aftermath scan [--keep]` | 立刻扫描，与上次基线对比 |
| `/aftermath roots` | 打印解析出的观测根 |
| `/aftermath roots --suggest` | 列出常用目录哪些已经盯上、哪些还没，并给出可直接粘的 yml |
| `/aftermath roots --add <路径>` / `--remove <路径>` | 预览加/减之后会变成什么样子，并给出可粘贴的 yml（不替你改配置） |
| `/aftermath status` | 配置、存档位置、记录条数 |
| `/aftermath doctor` | 自检：设置命名空间是否就绪、schema 从哪加载 |
| `/aftermath help` | 帮助 |

`--save` 把完整报告写到 `$DSH_HOME/state/aftermath/reports/`。

## 给 agent 的工具

`aftermath_history`（只读，参数 `since` / `root` / `limit`）。装上之后 agent 可以自己查「上一轮删了什么」，不用你翻日志。

## 存档与隐私

```
$DSH_HOME/state/aftermath/
├── baseline.json              最近一次快照（空闲期对比用）
├── turns/2026-11-17.ndjson    逐轮变更记录
└── reports/                   --save 的报告
```

只记路径、大小、mtime，不读文件内容、不存正文；命令原文只保留 ≤180 字符的片段用于归因说明，命令里出现的绝对路径最多留 12 条（每条 ≤320 字符）。不启子进程，不联网，恢复命令只打印不执行。记录按 `retentionDays` 自动清理。

记录格式 `v: 2`。每条带 `kind`：`changes`（有变更）或 `quiet`（根内无变化但执行过写操作，只含命令摘要，不含变更表）。

### 声明了哪些能力

`package.json` 里 `dsh.capabilities` 声明 `fs:read`、`tools:register`、`network:ingress`，`dsh.labels` 声明 `remote-access`。

`network:ingress` 是给「变更记录」标签页那条只读路由用的：插件在运行时通过 `ctx.inject(['webServer'])` 动态注册 `GET /aftermath/recent`，dsh-standards 的静态检查看不到这种动态注册，所以会报一条 `C-11.5` 警告——声明是真实的，不是多写的。路由只接受 GET/HEAD，只返回已经落盘的记录（路径已按 `maskHome` 打码），没有写入或删除接口。

## 已知限制

- 只覆盖配置的根和深度，根之外看不到磁盘状态；根外只能靠「命令文本提到过哪些路径」间接提示，命令没提到的就无从得知。
- 观测根没扫全（条目超上限、子目录读不到）时，那个根整根跳过，报告开头直接写「本轮观测不完整」，不会把没扫到的算成删除；这轮也不更新基线。
- `moved` 是启发式判断（同名 + 同大小 + mtime 相近），报告里会标注。
- 归因是证据强度分级，标 `？` 就是没有证据。
- 调用区间依赖宿主给出 `tool/result`：命令用 `Start-Process` 或 `&` 拉起后台进程时，改动会发生在区间结束之后，只能落到宽窗。
- 跨进程、跨会话的手动改动只能落进「时间窗内」或「无法归因」。
- 不自动还原：只存路径不存内容，还原是 rollback 类插件的事。
